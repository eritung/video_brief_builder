# 影音需求生成器 V1.3 Prototype

純前端、可直接部署到 GitHub Pages 的影音需求簡報工具。

## V1.3 核心邏輯

- **字幕 B 決定結構**：重剪後字幕 B 是最終影片的時間軸、片段順序與台詞分段基準。
- **字幕 A 決定文字正確性**：影音夥伴提供的字幕 A 用來校正 B 的轉錄錯字，並判斷原始片段是否被移除或調換。
- **簡報依 B 時間排序**：需求編輯、預覽與 PPTX 都以新版 B 的時間順序為主。
- **A 有、B 沒有的片段**：標成「移除」，並盡量插回新版時間軸中相鄰的上下文位置。

## V1.3 分段操作

分段確認改在字幕 B 上執行：

- `Enter`：從游標位置拆成下一段。
- 段落開頭 `Backspace`：與上一段合併。
- `Shift + Enter`：只在同一段內換行，不新增台詞區塊。
- `⌘/Ctrl + Enter`：切換「這句另起一頁」。
- 仍保留「合併上一段／下一段」按鈕作為滑鼠操作備援。

拆分／合併後會保留目前瀏覽位置，不再每次跳回分段區頂端。

## A 文字校正方式

1. 先用 B 建立新版台詞區塊。
2. 對每個 B 區塊搜尋字幕 A 中最接近的連續內容。
3. 高信心配對會直接在分段頁顯示 A 校正後文字。
4. 中等信心只顯示「A 可能對應」供確認，不強制覆蓋。
5. 進入需求編輯後，已匹配片段正式以 A 文字＋B 時間輸出。
6. B 找不到 A 對應的內容標成「疑似新增」。

## PPTX 與 JSON

- `.pptx`：正式輸出；可上傳 Google Drive 後以 Google 簡報開啟。
- `.json`：只保存本工具的編輯進度，之後重新匯入工具繼續製作，不是 Google 簡報格式。

## 本機使用

直接開啟 `index.html`。若瀏覽器限制本機腳本，可使用任意靜態伺服器。

## 部署到 GitHub Pages

1. 建立 GitHub repository，例如 `video-brief-builder`
2. 將此資料夾全部檔案上傳到 repository 根目錄
3. GitHub → Settings → Pages
4. Source 選 `Deploy from a branch`
5. Branch 選 `main`，Folder 選 `/ (root)`
6. 儲存後即可從 GitHub Pages 網址使用

## 注意

目前仍是 prototype。若影片包含大量重複句、多人同時說話、極大幅度改寫或重複使用相同台詞，A／B 自動配對仍可能需要人工確認。
