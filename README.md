# Video Brief Builder V2.1

瀏覽器本機版影音需求簡報工具。

## V2.1 重點

- **Text-first / Time-later 核心改版**：A/B 先移除時間軸與 cue 分段，只看純文本差異；等文本校正與分段確認後，才回填 A 的時間碼輸出需求。
- **降低字幕換行誤判**：B 的換行、cue 切法與 A 不同時，不會因為「這一段 B 沒看到某些字」就直接標成移除。
- **Step 3 先顯示校正後文本**：進入分段頁前，先用 A 的正式文字校正 B 的轉錄錯字；你分段時看到的是「A 校正後、符合 B 剪輯結果」的文字。
- **部分文字移除仍保留指定格式**：若某段文字真的從 B 全文消失，PPTX 會顯示完整 A 原句，並將被刪字串紅色刪除線標示，同時產生「移除部分文字」需求。
- **時間軸只用於輸出基準**：PPTX 不顯示 B 時間軸；所有需求都以 A 的來源時間碼描述「從 A 哪裡移除／搬移／調整」。
- **順序調換仍會標示來源 A 時間**：例如「順序調換｜從 A 00:01:14:16–00:01:27:17 移至此處」。
- **低信心匹配改成最佳候選優先**：只要 A 候選明顯勝過第二名，就直接用 A 校正，不再先顯示 B 錯字。
- **近距離分段差異不標記搬移**：若文字來源只是 A 相鄰 cue 或數秒內的連續段落，視為字幕切法不同並自動整合；只有來源距離遠、順序明顯打破時，才標記「從 A 移至此處」。
- **完全前端處理**：字幕解析、文本比對、分段、需求編輯、LocalStorage 與 PPTX 產出都在瀏覽器 JavaScript 執行；目前沒有後端。

## GitHub Pages

整個資料夾可直接部署到 GitHub Pages；需保留 `vendor/` 內的 `jszip.min.js` 與 `pptxgen.min.js`。

## 檔案結構

```text
index.html
styles.css
app.js
vendor/
  jszip.min.js
  pptxgen.min.js
.nojekyll
```
